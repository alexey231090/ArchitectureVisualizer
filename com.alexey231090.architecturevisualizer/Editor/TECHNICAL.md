# Техническая документация

> ⚠️ ВНИМАНИЕ: Плагин меняет направление! Теперь основной фокус — Event Tracking и система заметок для отладки. Таблицы зависимостей и Script Details считаются устаревшими и будут убраны в будущих версиях. Пока они доступны, но не развиваются. Ничего не удалять без отдельной команды: сначала только комментировать и тестировать!

## Актуальная архитектура

### Основные компоненты

#### 1. ArchitectureVisualizerWindow
Главное окно плагина, реализующее интерфейс пользователя для Event Tracking.

**Основные функции:**
- Управление вкладкой Event Tracking
- Добавление, редактирование, удаление цепочек (paths) и шагов (steps)
- Отображение отслеживаемых переменных, поддержка вложенных, коллекций, словарей
- Многострочные комментарии
- Поддержка кириллицы
- Подсветка изменений и обновление значений в реальном времени

**Ключевые методы:**
- `UpdateEventTracking()` — обновление UI Event Tracking
- `UpdateTrackedValuesData()` — обновление значений переменных
- `GetValue()` — получение значения (поддержка вложенных, коллекций, словарей)
- `UpdateHighlightColors()` — подсветка изменений

#### 2. EventTrackingManager
Компонент для хранения и управления всеми цепочками (paths) и шагами (steps).

#### 3. ScriptPickerWindow (новое)
Отдельное окно-помощник для выбора скрипта. Содержит поле для поиска и динамически фильтруемый список. Вызывается из окон добавления путей и шагов для улучшения UX.

**Основные функции:**
- Сериализация и сохранение цепочек и шагов
- Добавление, удаление, редактирование путей и шагов
- Интеграция с EditorPrefs

**Ключевые методы:**
- `AddPath()`, `DeletePath()`, `AddStep()`, `DeleteStep()`, `SavePaths()`, `LoadPaths()`

### UI Компоненты

- **Event Tracking** — основная вкладка для работы с цепочками, шагами, отслеживанием переменных и заметками
- (Устаревшее) **Tables** — таблицы зависимостей (будет удалено)
- (Устаревшее) **Script Details** — детальный анализ скриптов (будет удалено)

### Структура данных

#### TrackingPath
```csharp
public class TrackingPath
{
    public string pathName;
    public string description;
    public List<TrackingStep> steps;
    public bool isTracking;
    public string lastUpdateTime;
}
```

#### TrackingStep
```csharp
public class TrackingStep
{
    public string scriptName;
    public List<string> variableNames; // Список отслеживаемых переменных
    public string comment;
    public List<TrackedInstance> trackedInstances;

    // Поля для отслеживания не-MonoBehaviour классов
    public bool isMonoBehaviourTracked; 
    public string hostScriptName;       // Имя хост-компонента
    public string instanceFieldName;    // Имя поля/свойства с экземпляром
}
```

#### TrackedInstance
```csharp
public class TrackedInstance
{
    public int instanceId; // Теперь используется HashCode экземпляра
    public string lastValue; // Используется для обратной совместимости
    public double highlightStartTime;
    public double lastCheckTime;
    public UnityEngine.UIElements.Label valueLabel;
    public Component component; // Может быть null для не-MonoBehaviour
}
```
Новый класс `MultiVarTrackedInstance` наследуется от `TrackedInstance` и хранит значения для нескольких переменных.

### Техническая заметка: кириллица в EditorWindow

- Для поддержки кириллицы используется шрифт Roboto (ttf) и явное применение его к Label/TextField.
- В Label и TextField кириллица теперь отображается корректно на всех платформах, баг с вводом полностью решён, никаких костылей и кнопки "Рус" больше не требуется.
- Можно свободно использовать многострочные комментарии и описания на русском языке.

### Event Tracking (актуализация)

- Теперь в Event Tracking выводится тип переменной рядом с её значением, а для TextMeshProUGUI — отображается именно текст, а не ссылка на объект.
- Если отслеживаемый объект был уничтожен, вместо ошибки MissingReferenceException выводится [Destroyed].
- Переменные, которые ни разу не менялись, отображаются серым цветом, а изменённые — белым, что удобно для анализа.

## Event Tracking (актуализация)

### Архитектура
- EventTrackingManager — хранение и управление всеми цепочками (paths) и шагами (steps)
- ArchitectureVisualizerWindow — вкладка Event Tracking, UI для управления путями и шагами
- AddPathWindow, EditPathWindow, AddStepWindow — модальные окна для добавления/редактирования путей и шагов

### Возможности
- Добавление/редактирование/удаление путей и шагов
- Выбор скрипта и переменной для каждого шага
- Многострочные комментарии
- Английский интерфейс
- Поддержка кириллицы (работает "из коробки")
- Поддержка массивов, коллекций, множественных экземпляров объектов
- Подсветка изменений (fade/highlight)
- Реальное время обновления значений
- Устойчивость к ошибкам (NullReference и др.)

### Назначение Event Tracking
Event Tracking — это инструмент для отладки с заметками. Вы строите путь (цепочку) из шагов, и в каждом шаге пишете заметку (комментарий), поясняющую, что и зачем отслеживается. В результате формируется полный путь с пояснениями, который сохраняется (например, в json). Это позволяет:
- Воспроизводить сложные сценарии отладки и анализа
- Быстро возвращаться к нужным последовательностям действий
- Не выискивать заново, как что работает — вся логика и ваши комментарии всегда под рукой
- Использовать путь и заметки как живую документацию по архитектуре и поведению системы

Путь и заметки — это единое целое для отладки, анализа и документации.
